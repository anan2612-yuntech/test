# 電子仙女棒（NUCLEO-G474RE 期中專題）

> 一句話：輸入一個數字，就像用打火機點燃一根仙女棒——火光從那個位置往兩側蔓延、亮度噼啪漸弱，燒完「碳化」變黑，5 秒後又能重新點燃。

本專案依課程「README 牛奶瓶版」10 段範本撰寫：規格書七個欄位落在第 1～5、9 節，第 6～8、10 節自行補充。

專案原始碼位於 [`tt/`](tt/) 子目錄（STM32CubeIDE 工程，工程名 `tt`）。

---

## 1. 情境故事：誰、在哪、遇到什麼麻煩

中秋、跨年、演唱會……手上那根仙女棒最迷人的，就是「點燃 → 火花從一點往兩端劈啪擴散 → 燒到最後整根變黑 → 想再玩只能拿新的」這整個過程。

問題是：真仙女棒有火、有煙、有危險，室內或教室裡不好示範，而且燒完就沒了。

所以做一個**電子替身**：用 NUCLEO-G474RE 板子上排成一列的 7 顆 LED 當作仙女棒本體，透過電腦序列埠「點火」，重現火光擴散、漸弱、碳化、5 秒後復活的完整體驗——可重複玩、零危險。

## 2. 替身對照：故事裡的模組 → 板上接法

| 故事裡的真實物件 | 板上的替身 | 怎麼做 |
|---|---|---|
| 仙女棒本體的光 | 7 顆 LED（排成燈條） | PA8 / PA9 / PA10 / PA11 / PB6 / PB7 / PB0，用 TIM1 / TIM4 / TIM3 的 PWM 控制亮度 |
| 打火機（點火） | 電腦序列埠輸入 `1`～`7` | USART2（PA2/PA3，115200 8N1）接收單一字元，數字即點燃位置 |
| 火花向兩側蔓延 | 燃燒中心左右外擴 | 主迴圈每 100 ms 讓每個燃燒中心 `spread_radius++`，點亮左右各一格 |
| 燒到最後變黑（碳化） | `led_carbonized[]` 旗標 | 亮度歸零後設 1，模擬「碳化後不能再點」 |
| 換一根新的（5 秒復活） | `carbonize_timer[]` 計時 | 碳化滿 5000 ms 自動解除，恢復可再點燃 |
| 火光忽明忽暗、漸弱 | PWM 平滑追隨 | 每 25 ms 用「差距 1/3+1」比例追隨公式逼近目標亮度 |

多點同時輸入即可「同時點燃好幾根」——每個位置各自當一個燃燒中心，各自向外擴散、各自碳化。

## 3. 功能與驗收條件：動作、預期、實測結果

| # | 動作 | 預期結果 | 實測結果 |
|---|---|---|---|
| 1 | 送出 `4` | 第 4 顆（PA11）先亮到最亮，接著向左右兩側（3→2→1、5→6→7）依序點亮擴散 | ⬜ 待實測 |
| 2 | 連續送出 `1` `2` … `7` | 可同時有多個燃燒中心，各自往兩側蔓延，互不干擾 | ⬜ 待實測 |
| 3 | 任一顆燒到底 | 該顆亮度平滑降到 0、熄滅，並進入「碳化」不可再點 | ⬜ 待實測 |
| 4 | 碳化後立刻再送同一數字 | 該位置**不**反應（已碳化）；送其他未碳化位置則正常點燃 | ⬜ 待實測 |
| 5 | 碳化後靜待 5 秒 | 滿 5 秒後該位置自動解除碳化，可再次被點燃 | ⬜ 待實測 |
| 6 | 送出 `0` 或 `8`、字母等非法字元 | 直接忽略，不崩潰、不越界 | ⬜ 待實測 |
| 7 | 全程觀察亮度變化 | 點亮與熄滅皆為平滑漸變（呼吸感），非硬切 | ⬜ 待實測 |

## 4. 用到的技術（第 3～7 週勾選表）

> 週次請依課程投影片對照勾選；以下為本專案實際用到的技術。

- [x] **GPIO** 輸出（7 路 LED 腳位由 TIM 通道接管）
- [x] **中斷 / NVIC**：USART2 接收中斷（`HAL_UART_Receive_IT` → `HAL_UART_RxCpltCallback`）
- [x] **Timer / PWM 輸出**：TIM1（CH1~CH4）、TIM4（CH1~CH2）、TIM3（CH3），Prescaler=169、Period=999 → **PWM 1 kHz、解析度 0~1000**
- [x] **UART 非同步通訊**：USART2，115200 8N1，無流量控制，輪詢式持續掛接收中斷
- [x] **SysTick / 時基排程**：`HAL_GetTick()` 做非阻塞分段計時（25 ms / 100 ms / 5000 ms）
- [x] **系統時鐘 PLL**：HSI16 → PLL（M=DIV4, N=85, P/Q/R=DIV2）→ **SYSCLK 170 MHz**，FLASH_LATENCY_4
- [ ] ADC / I2C / SPI / DMA（本專案未使用）

## 6. 建置與執行：開發環境、燒錄步驟、終端機設定、命令

**開發環境**
- STM32CubeIDE（工程由 CubeMX **6.18.1** 產生），韌體包 **STM32Cube FW_G4 V1.6.3**，工具鏈 GCC
- MCU：STM32G474RET6（LQFP64），板子：NUCLEO-G474RE
- 系統時鐘：170 MHz（HSI16 → PLL M=DIV4 / N=85 / P/Q/R=DIV2，VCO 340 MHz）

**燒錄步驟**
1. 用 USB 連接 NUCLEO 板（板載 ST-LINK）
2. STM32CubeIDE → `File > Open Projects from File System…` → 選 `tt/` 資料夾
3. 先 `Build`，再 `Run`（或 `Debug`），由板載 ST-LINK 燒錄並執行

**終端機設定**
- 連到 ST-LINK 的虛擬 COM 埠（USART2 預設已接到 ST-LINK VCP）
- **115200 bps，8 資料位，無同位，1 停止位，無流量控制**
- 任一序列埠工具皆可（PuTTY / Tera Term / Arduino Serial Monitor…）

**命令**
- 直接輸入單一數字 `1`～`7` 即點燃對應位置（例：`4` = 第 4 顆 LED）
- 可連續、可多位同時；輸入 `0`、`8` 或字母會被忽略

## 7. 程式結構：哪個檔做什麼、ISR 與主迴圈分工

| 檔案 | 作用 |
|---|---|
| `tt/Core/Src/main.c` | **核心邏輯**：初始化 7 路 PWM + USART2；主迴圈三段定時（碳化解除 / 外擴 / 亮度漸變）；`HAL_UART_RxCpltCallback` 解析 `1`~`7` |
| `tt/Core/Inc/main.h` | 腳位巨集定義、`Error_Handler` 等宣告 |
| `tt/Core/Src/stm32g4xx_it.c` | 例外/中斷向量：`USART2_IRQHandler → HAL_UART_IRQHandler(&huart2)`、`SysTick_Handler → HAL_IncTick()` |
| `tt/Core/Src/stm32g4xx_hal_msp.c` | MSP 初始化：各週邊的 GPIO / 時鐘 / NVIC |
| `tt/Core/Src/system_stm32g4xx.c` | 系統時鐘基礎設定（CubeMX 產生） |
| `tt/tt.ioc` | CubeMX 設定檔（腳位、TIM、USART2、RCC） |
| `tt/Drivers/` | STM32G4 HAL 驅動 + CMSIS（函式庫，勿改） |

**ISR 與主迴圈的分工（重點）**
- **USART2 RX 中斷只做「輕」的事**：收到 1 byte → 判斷 `'1'`~`'7'` → 設定 `active_centers[index]=1`、`spread_radius[index]=0`、重設 `spread_timer` → 立刻重新掛 `HAL_UART_Receive_IT`。中斷內不點燈、不做迴圈，避免中斷佔用過久。
- **主迴圈做「重」的事**（非阻塞，用 `HAL_GetTick()` 分三段計時）：
  1. **碳化解除**（每圈檢查）：`led_carbonized[i]==1` 且已過 5000 ms → 清 0；
  2. **外擴**（每 100 ms）：對每個 `active_centers[c]` 點亮 `left=c-半徑`、`right=c+半徑`，半徑 +1，兩端都出界則關閉該中心；
  3. **亮度狀態機 + PWM 寫入**（每 25 ms）：`led_burn_state` 1→設目標 1000 轉 2；2→目標每次 −75，降到 ≤100 則歸 0、碳化、記時；最後 `led_pwm_val` 以 `(差距)/3+1` 平滑追隨，再用 `__HAL_TIM_SET_COMPARE` 寫入 7 路比較值。

（演算法核心：三段計時器 + 每顆 LED 獨立狀態機 + 比例追隨平滑，全部在 `while(1)` 內非阻塞完成。）

## 10. 已知限制：哪些用替身、換真貨要改哪裡

- **LED 是替身**：真仙女棒是化學燃燒＋火花＋煙＋熱；本專案只用 7 顆 LED 的 PWM 亮度模擬「漸弱與碳化」，沒有真實火光。
- **碳化時間固定 5 秒**（常數 `5000`），不是依「燃料量」動態計算。
- **位置數上限 = 7 顆 LED**；再多就需要擴充燈數。
- **UART 只認 ASCII `'1'`~`'7'`**，其餘字元忽略；沒有回傳 ACK / 狀態回報。
- **亮度上限 1000**（對應 Period=999），PWM 1 kHz；若要更細膩需調高 Period 或改更高頻。
- **HSE 24 MHz 雖在 `.ioc` 標成外部振盪器，實際時鐘源仍用 HSI16**；若真要改用 HSE，需重算 PLL（M/N/P/Q/R）。
- **換「真貨」要改的地方**：把 LED 換成實際燈串 / 繼電器 / WS2812，需要改驅動方式（移位暫存器或位址式燈條通訊），並重新設計亮度映射。
